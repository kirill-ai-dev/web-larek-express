# Бэкенд WebLarek.

## Используемые технологии и решения

- Typescript в качестве основного языка проекта
- Mongodb и ODM Mongoose для хранения данных пользователей
- Node.js в качестве среды выполнения

Перед отправкой работы на проверку убедитесь что она соответствует требованиям проектной работы

## Локальный запуск

Скопируйте `.env.example` в `.env`, укажите адрес MongoDB в `DB_ADDRESS`
и задайте два разных случайных секрета: `AUTH_ACCESS_TOKEN_SECRET`
и `AUTH_REFRESH_TOKEN_SECRET`. Получить один секрет можно командой
`node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`.
Повторите её для второго секрета. Файл `.env` не добавляется в Git.

После `npm ci` запустите сервер командой `npm run start` или `npm run dev`.
Срок access-токена по умолчанию — 10 минут, refresh-токена — 7 дней.
Настройки берутся из `AUTH_ACCESS_TOKEN_EXPIRY` и `AUTH_REFRESH_TOKEN_EXPIRY`.
Для фронтенда с cookie используется адрес из `ORIGIN_ALLOW`.

## Проверка авторизации

`npm test` собирает backend и проверяет пять маршрутов `/auth` на отдельной
временной базе MongoDB на `127.0.0.1:27017`. Тестовая база удаляется после
проверки; база приложения не используется. MongoDB должна быть запущена.

Пароль хешируется встроенной функцией `scrypt` со случайной солью перед
сохранением. Поля `password` и `tokens` скрыты при
обычном поиске пользователя. В ответах API передаются только имя, email и
access-токен; refresh-токен находится в httpOnly-cookie. При обновлении сессии
старый refresh-токен заменяется новым, при выходе удаляется только текущая сессия.
